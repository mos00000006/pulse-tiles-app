1. CREATE THE CLOUD FIRESTORE DATABASE
   Open:
   https://console.firebase.google.com/project/pulsetiles-sales-app/firestore
   Click Create database.
   Choose Standard edition if an edition is requested, and use the
   (default) database ID. Select the database location before confirming.
   Start in production mode.

2. PUBLISH THE ACCESS RULES
   Open the database's Rules tab.
   Replace its rules with the COMPLETE contents of firestore.rules in this
   ZIP, then click Publish. The administrator email is already filled in.
   The production default denies all app access until these rules are
   published.

   The included rules restrict customer/quotation records to their owner
   and administrators. Only administrators approve staff and set roles.
   Staff discounts are limited to 5%; administrators can approve more.
   The primary administrator is protected from team-screen changes.

3. AUTHORISE YOUR HOSTNAME
   In Authentication > Settings > Authorised domains, add the hostname of
   your GitHub Pages app, for example yourname.github.io. Enter only the
   hostname; leave off https:// and the repository path. Add any custom
   hostname you use as well.

4. UPLOAD THIS UPDATED APP TO GITHUB
   Extract the ZIP and replace the repository files with its contents.
   Keep index.html, sales-app/ and data/ side by side at the repository root.
   Wait for GitHub Pages to publish the update. Reload the app and check
   that version 1.1.2 is shown. Use Update App if prompted.

5. SIGN IN AS THE ADMINISTRATOR
   Email: moyanamoses006@icloud.com
   Password: the one you chose privately in Firebase Authentication.
   Successful sign-in opens the Pulse sales workspace. If you see a missing
   permissions error, check step 2 in this same project. Live login and
   Firestore access have not been verified from this development workspace.

6. ADD OTHER USERS WHEN READY
   Open the account menu > Manage Sales Team.
   Enter each staff member's full name, email, role and temporary password.
   Salesperson access is limited to their own customers and quotations.
   Additional administrators can see team records and manage staff access.
   Existing accounts keep their passwords when approved. Staff can use
   Forgot password on the login screen when required.
